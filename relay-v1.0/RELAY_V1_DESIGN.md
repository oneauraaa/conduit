# Relay v1.0 Fine-Tuning Design

## Goal

Fine-tune Ornith 1.5 9B for Conduit MCP tool use with QLoRA on a 16 GB RTX 5070 Ti, teaching accurate tool selection and arguments plus Auto Mode approval behavior, then export a separate Q4_K_M GGUF for ordinary local inference.

## Scope

The project trains on text-only Conduit conversations. The model remains multimodal-capable, but the initial dataset does not require image tensors because the target behavior is tool selection and policy. The vision portion of the base model is frozen. The original `relay-v1.0/Ornith-1.5-9B-Q4_K_M.gguf` is an inference reference and is never overwritten.

The model learns two policy contexts:

- In normal/manual context, read-only and ordinary UI actions may be called when the user asks for them.
- In Auto Mode, potentially state-changing or destructive actions require an approval turn before the tool call. The examples explicitly distinguish safe inspection (`pwd`, `ls`, `git status`) from risky shell commands and treat app termination, clipboard replacement, and other catalogued risky tools as approval-gated.

The training data uses Ornith's native tool-call syntax from its Hugging Face chat template:

```text
<tool_call>
<function=tool_name>
<parameter=parameter_name>
value
</parameter>
</function>
</tool_call>
```

## Architecture

The pipeline is one Python entry point under `relay-v1.0` with subcommands:

1. `prepare` validates the canonical tool schema, writes deterministic JSONL conversations, and creates a held-out evaluation split.
2. `smoke` verifies the Unsloth/Transformers/CUDA/model-loading path and runs a short bounded training step without committing a full run.
3. `train` loads the Hugging Face BF16 checkpoint through Unsloth in NF4 4-bit mode, applies language-model LoRA adapters, and saves an adapter checkpoint.
4. `export` merges the adapter into the base checkpoint and exports Q4_K_M through Unsloth's exporter, with a llama.cpp fallback when the model-specific exporter fails.
5. `evaluate` loads the resulting adapter or GGUF endpoint and scores held-out tool name, required arguments, exact XML structure, and Auto Mode approval cases.

The base model is `ornith-ai/Ornith-1.5-9B`, not the existing GGUF. The trainer downloads or reuses the BF16 safetensors checkpoint from the Hugging Face cache. QLoRA keeps the base weights 4-bit during training; it does not claim to train the already-quantized GGUF directly.

## Components and files

- `relay-v1.0/train_relay.py`: CLI entry point, environment checks, dataset preparation, Unsloth training, merge/export, and evaluation.
- `relay-v1.0/conduit_tools.json`: canonical JSON Schema-style definitions for all Conduit MCP tools, including risky flags and concise descriptions.
- `relay-v1.0/data/conduit_sft.jsonl`: deterministic training conversations with `messages`, `tools`, and a policy label used only for dataset auditing.
- `relay-v1.0/data/conduit_eval.jsonl`: held-out conversations not used for gradient updates.
- `relay-v1.0/config.json`: reproducible paths and training defaults for the 16 GB GPU.
- `relay-v1.0/README.md`: setup, commands, disk requirements, expected VRAM range, and recovery instructions.
- `relay-v1.0/output/adapter`: LoRA adapter checkpoint.
- `relay-v1.0/output/merged`: merged Hugging Face checkpoint used for conversion.
- `relay-v1.0/output/Ornith-1.5-9B-Relay-v1.0-Q4_K_M.gguf`: final quantized deployment model.
- `relay-v1.0/output/evaluation.json`: held-out evaluation report.

Generated weights, caches, GGUF files, and Python bytecode are excluded from version control. The existing reference GGUF is retained locally but is not committed by this task.

## Dataset design

Each JSONL record contains a complete conversation. The system message includes the current Conduit platform/mode policy, and the `tools` array contains the canonical MCP definitions. Assistant tool calls use Ornith's XML format. Tool responses are represented with the `tool` role using compact JSON or plain text. Examples cover:

- screen and display inspection;
- accessibility lookup followed by click;
- list windows followed by focus or bounds changes;
- DuckDuckGo search;
- keybind discovery before a shortcut;
- safe shell inspection;
- Auto Mode approval before risky shell commands;
- Auto Mode approval before quit, clipboard replacement, and other risky tools;
- refusal to invent unavailable portal capabilities on Hyprland;
- multi-step calls where the result of one tool determines the next call.

The initial corpus is curated and deterministic rather than generated by a model. It uses a 90/10 train/evaluation split with a fixed seed. The preparation command validates every tool name, required argument, risky flag, and assistant XML call before writing files. Policy labels remain metadata for auditing and are not exposed as a separate target token.

## Training configuration

The initial configuration is conservative for the 16 GB card:

- 4-bit NF4 loading with double quantization;
- BF16 compute when supported, otherwise FP16;
- sequence length 2,048;
- micro-batch size 1;
- gradient accumulation 8;
- gradient checkpointing enabled;
- paged 8-bit AdamW;
- LoRA rank 16, alpha 32, dropout 0.05;
- language attention and MLP projections targeted; vision layers frozen;
- two epochs, low learning rate, deterministic seed;
- no image batches and no packing across separate conversations.

The smoke command runs a small bounded step before a full run. If the card cannot fit the selected sequence length, the command reports the observed peak memory and recommends lowering sequence length before changing the model or quantization target.

## Export and compatibility

The exporter first saves a merged 16-bit Hugging Face checkpoint, then writes a BF16 GGUF and quantizes it to Q4_K_M. It verifies that the output file exists, is non-empty, and reports its size. If Unsloth's Qwen3.5 conversion path fails, the script invokes the bundled llama.cpp converter and quantizer with the same output target. The final GGUF is kept separate from the original reference file.

The script prints the installed Unsloth, Transformers, PyTorch, CUDA, and GPU versions before loading. A clear compatibility error is returned for an old Transformers sidecar, missing CUDA, absent model files, insufficient disk space, or a dataset/schema mismatch.

## Testing

Validation is layered:

1. Pure Python dataset tests run without a GPU: schema completeness, deterministic split, risky-tool labels, valid XML tool calls, and Auto Mode approval examples.
2. An Unsloth dry-run loads the model/tokenizer and resolves LoRA settings without starting a long run.
3. A bounded smoke run performs a few optimizer steps and saves a temporary adapter.
4. Export verification checks merged files, GGUF creation, Q4_K_M quantization, and output size.
5. Held-out evaluation checks exact tool names, required parameters, XML parseability, and approval behavior. It does not claim general intelligence or replace manual testing in Conduit.

## Non-goals

This version does not add a new Conduit runtime model provider, change MCP tool behavior, train on private screen recordings, add image examples, or promise that every arbitrary shell command can be classified safely. Auto Mode remains the runtime authority for risky-tool approval; Relay's training examples only make the model more likely to cooperate with that policy.
